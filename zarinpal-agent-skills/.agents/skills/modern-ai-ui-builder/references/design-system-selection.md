# Design-System Selection Guide

Design systems provide design principles, components, patterns, and standards. Use them to accelerate design decisions and create a coherent interface.

When implementing with shadcn/ui, use one of these systems primarily as a **reference**, unless the user explicitly requests its component library.

## Material Design

Best fit:

- Consumer-facing products
- Mobile-first experiences
- Familiar interaction patterns
- Products benefiting from clear motion and elevation guidance

Primary topics:

- Typography
- Color
- Layout
- Spacing
- Components
- Motion
- Accessibility

Official resource:

https://m3.material.io/

## Ant Design

Best fit:

- Enterprise applications
- Admin dashboards
- Management panels
- Dense tables
- Complex forms
- Data-heavy products

Use it for ideas about information density, workflow layout, filters, and enterprise interaction patterns.

Official resource:

https://ant.design/

## IBM Carbon Design System

Best fit:

- Enterprise products
- Analytical applications
- Accessibility-sensitive interfaces
- Token-driven design systems
- Data visualization

Primary topics:

- Components
- Design tokens
- Typography
- Color
- Grid
- Accessibility
- Patterns
- Data visualization

Official resource:

https://carbondesignsystem.com/

## Microsoft Fluent 2

Best fit:

- Productivity applications
- Microsoft-like ecosystems
- Integrated workspaces
- Interfaces with rich interaction and navigation

Primary topics:

- Components
- Typography
- Color
- Layout
- Icons
- Design tokens
- Accessibility
- Motion
- Interaction

Official resource:

https://fluent2.microsoft.design/

## Bootstrap 5 Design System

Best fit:

- Rapid conventional layouts
- Familiar web patterns
- Figma prototyping
- Projects that value speed and predictability over a distinctive visual language

Common patterns:

- Colors
- Typography
- Buttons
- Forms
- Cards
- Tables
- Navigation
- Modals
- Alerts
- Pagination

Figma resource:

https://www.figma.com/community/file/1044316192441037087/bootstrap-5-design-system-ui-kit

## Selection rule

Choose one primary reference according to the product's users and workflow. Borrow principles, not branding. Do not mix multiple systems without a clear design rationale.
